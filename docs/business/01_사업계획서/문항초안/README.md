# 문항초안 — Q1~Q4 배분 원칙

> 목적: 같은 내용을 두 문항에서 반복하지 않고, 심사위원이 Q1부터 Q4까지 순서대로 읽으면 설득 논리가 저절로 완성되게 하는 것.

## 1. 전체 흐름 — 네 문항이 하나의 논리

| 순서 | 읽는 사람이 갖게 되는 생각 | 담당 문항 |
| --- | --- | --- |
| ① 문제 | "이런 문제가 실제로 있구나" | **Q1** |
| ② 손해·기회비용 | "이걸 방치하면 이만큼을 잃는구나" (수치) | **Q1** |
| ③ 솔루션과 해결 근거 | "이 방법이면 풀리겠구나, 이 팀이면 만들겠구나" | **Q2** |
| ④ 이익·효과 | "그래서 돈이 이만큼 되고 이만큼 커지는구나" (수치) | **Q3** |
| ⑤ 발전 방향 | "앞으로 더 좋아지겠구나" | **Q4** |

②와 ④에 수치가 없으면 나머지가 아무리 좋아도 설득되지 않음. 이 두 칸을 먼저 채울 것.

## 2. 문항별로 쓸 것 / 쓰지 말 것

### Q1. 문제 인식 — 개발 동기·목적·목표 시장
**쓸 것**
- 어떤 문제가 있는가 (조사로 확인한 사실)
- 그 문제를 어떻게 알게 되었는가 (인터뷰·설문·통계 등 조사 경로)
- **그 문제 때문에 누가 얼마를 잃는가** — 이용자 쪽 손해, 매장 쪽 기회비용, 수치로
- 목적
- 목표 시장 (TAM·SAM·SOM, 공식 통계 기준)

**쓰지 말 것**: 기능 설명, 개발 방법, 경쟁사 비교표

### Q2. 실현가능성 — 개발 방안·준비 정도·차별화 방안
**쓸 것**
- 어떻게 만들 것인가 (데이터 확보 / 유저 확보 / 활성화 / 검증 지표)
- 지금 어디까지 되어 있는가 (제품·팀·조사·제도·자금)
- 기존 서비스와 무엇이 다르고, 그 차이가 통한다는 근거

**쓰지 말 것**: 문제를 다시 설명하는 문단, 시장 규모, 매출 추정, 멘토링 회고
→ 문제는 Q1에서 이미 읽었으므로 "Q1에서 확인한 ○○ 문제에 대해" 한 구절로만 받고 바로 방법으로 갈 것.

### Q3. 성장전략 — 사업화 계획·추진일정·자금
**쓸 것**
- 수익모델과 단가, 매출 추정 근거
- 시장 진입 순서와 확장 경로
- 추진 일정, 자금 소요·조달

**쓰지 말 것**: 기능 설명, 문제 재설명

### Q4. 향후 발전방안 — 멘토링 후 발전 방향·개선점
**쓸 것**
- 멘토링으로 무엇이 어떻게 바뀌었는가 (변경 전 → 후)
- 남은 과제와 다음 라운드 계획

**쓰지 말 것**: Q2에 이미 쓴 기능·준비 현황 반복

## 5. 문체 규칙 (2026-08-10 확정)

팀이 쓴 원문 두 개를 비교해 보면 문서마다 문체가 다릅니다. 이를 그대로 따릅니다.

| 문서 | 팀 원문 문체 | 예시 |
| --- | --- | --- |
| 참고 2 사업계획서 양식 | 개조식·명사형 종결 | "…문제를 반복적으로 **확인**", "…점에 **주목함**" |
| 참고 3 창업활동 보고서 | 서술형 존댓말 | "…불편사항을 **확인하였습니다**" |

**Q1·Q2·Q3(사업계획서 본문)는 항목별로 나눠 씁니다.**

- **사실·수치 나열** → 개조식(명사형 종결). 조사 경로, 설문 결과, 시장 규모, 준비 현황, 기능 목록.
- **논리 설명** → 서술형 존댓말. 왜 이 해결책인지, 왜 효과가 있는지, 차별화 근거, 한계와 대응.
- **참고 3 창업활동 보고서**는 전체를 서술형 존댓말로 씁니다.

**표는 수치·비교에만 사용합니다.** 팀 원문에는 표가 거의 없으므로, 시장 규모·경쟁 비교·As is/To be처럼 숫자나 대조가 격자로 들어가는 것만 표로 두고 나머지는 번호 목록으로 씁니다. 문서당 표 3~4개를 넘기지 않습니다.

## 6. AI 티가 나는 문장 — 반복 금지 목록

실제 검토에서 "어색하다"고 지적된 문장들의 원인입니다. 원본(참고 2·참고 3)에는 아래 패턴이 한 번도 나오지 않습니다.

### 6-1. 항목 제목에 결론을 매달지 않기

원본은 항목마다 **동작 하나 또는 관찰 하나**만 적습니다. "조사", "확인", "나타남", "분산됨", "판단", "시작".

- ✗ `④ 외국인들이 쓰는 방법과 그 한계를 조사 — 수요는 이미 존재함을 확인`
- ✓ `④ 이러한 불편을 해결하기 위해 외국인들은 어떤 방법을 사용하고 있는지 조사`

한 제목에 동작·관찰·결론 세 개를 압축하면 압축된 요약처럼 읽힙니다. 결론은 본문 마지막 문단에 둡니다.

### 6-2. 제목에 대시(—)로 핵심을 덧붙이지 않기

`제목 — 핵심결론` 구조는 슬라이드·블로그 문법입니다. 원본 참고 2·참고 3에는 대시가 쓰인 제목이 없습니다.
(단, `① 장소 데이터 — 공공 개방 데이터 결합`처럼 **제목 안에서 대상과 방법을 잇는 용도**는 허용)

### 6-3. "~함을 확인" 류 금지

- ✗ ~함을 확인 / ~음을 확인 / ~임을 알 수 있음 / ~라는 점을 시사 / ~에 의의가 있음
- ✓ ~나타남 / ~분산됨 / ~로 확인되었습니다 / 그냥 사실을 서술

관찰을 적는 것과 **내가 옳았음을 스스로 인증하는 것**은 다릅니다. 뒷쪽이 AI 티의 핵심입니다.

### 6-4. 해석보다 사실을 먼저

두괄식은 **사실**을 앞세우는 것이지 **해석**을 앞세우는 것이 아닙니다. 근거를 보여주기 전에 해석을 못 박으면 "정해 놓고 쓴 글"로 읽힙니다.

- ✗ (표 위에) "수요는 이미 존재합니다" → 표 → 끝
- ✓ "이미 나름의 방법으로 해결하고 있었습니다. 다만 한계가 있었습니다" → 표 → "정리하면, 없던 수요를 만드는 게 아니라 흩어진 행동을 모으는 일입니다"

### 6-5. 추상 주어 + 추상 동사 피하기

주어를 사람·행동으로, 동사를 눈에 보이는 것으로 바꿉니다.

- ✗ 조건이 같은 사람의 후기를 보여주는 **방식은** 구매 결정을 **바꿉니다**
- ✓ 나와 조건이 같은 사람의 후기를 보여주면 **구매 전환율이 올라갑니다**
- ✗ 이 **구조는** 큰 자본 없이도 리뷰가 **쌓입니다** (주술 불일치)
- ✓ 큰 자본을 들이지 않아도 리뷰가 쌓입니다

뒤에 숫자를 붙일 문장이면, **그 숫자가 말하는 그대로** 문장을 씁니다(전환율 3배 → "전환율이 올라갑니다").

### 6-6. 강조 부사 빼기

"실제로", "매우", "정말", "충분히"는 뒤에 근거 수치가 오면 불필요합니다.

## 7. 제출 문체 보정 규칙 (말투보정본 대조로 도출)

2026-08-12에 팀이 합본을 직접 다듬은 `말투보정본.md`와 원본을 줄 단위로 대조해 뽑은 규칙입니다. 내용은 그대로 두고 문체만 바뀐 것이 27개 문단이었습니다. **초안을 쓴 뒤 마지막에 이 절을 훑으며 한 번 고칩니다.**

### 7-1. 개조식 항목은 "~함"을 붙이지 않는다

| ✗ | ✓ |
| --- | --- |
| 정보를 지속적으로 요청**함** | 정보를 지속적으로 요청 |
| 어렵다는 점에 주목**함** | 어렵다는 점에 주목 |

번호 목록·불릿의 개조식 항목은 명사 또는 어간으로 끝냅니다. "~함"은 보고서 초고 티가 납니다.

### 7-2. 목적·계획 항목의 "~하는 것"은 명사형으로

| ✗ | ✓ |
| --- | --- |
| 검색 불편을 줄이는 것 | 검색 불편 **감소** |
| 리뷰 정보를 제공하는 것 | 실제 경험 정보 **제공** |
| 의사결정을 할 수 있도록 지원하는 것 | 의사결정을 할 수 있도록 **지원** |

### 7-3. 자기지칭은 GLOU. 주어가 없어도 되면 뺀다

| ✗ | ✓ |
| --- | --- |
| **[성명]은** K-beauty를 주제로 활동 | K-beauty를 주제로 활동 |
| **저희는** 같은 흐름을 측정하겠습니다 | **GLOU는** 같은 흐름을 측정합니다 |
| **저희가** 임의로 정한 수치가 아니라 | 예상 매출은 임의의 수치를 적용하기보다 |

### 7-4. 일상 동사를 문어 동사로

| ✗ | ✓ |
| --- | --- |
| 실적을 **보고 정하였습니다** | 실적을 **참고하여 설정하였습니다** |
| 단위를 **가져옵니다** | 기준선으로 **활용합니다** |
| 경로를 **잡았습니다** | 확보 경로를 **설정하였습니다** |
| 지표에 **넣은** 이유 | 검증지표에 **포함한** 이유 |
| 그대로 **쓰지는** 않습니다 | 그대로 **적용하지는** 않습니다 |
| 데이터베이스를 **채울** 수 있도록 | 데이터베이스를 **구축할** 수 있도록 |
| 문제가 **되지** 않도록 | 문제가 **발생하지** 않도록 |
| 조사에서 **나온 의견** | **사용자 조사 결과** |
| 둘 다 **잘 쓰이지 않습니다** | 두 기능의 **사용 목적을 구분합니다** |

### 7-5. 지시어는 "해당"으로, 연결어를 붙인다

| ✗ | ✓ |
| --- | --- |
| **이** 단위를 그대로 쓰지는 않습니다 | **다만 해당** 단위를 그대로 적용하지는 않습니다 |
| 손익 시점**도 같은 방식으로 봅니다** | 손익분기 시점 **역시** 유사 플랫폼 사례를 참고하여 검토합니다 |
| 시장 근거는 확인되어 있습니다 | **해당 사업 확장의** 시장 근거도 확인할 수 있습니다 |

### 7-6. 용어를 한 단계 정확하게

| ✗ | ✓ |
| --- | --- |
| 지표 | 검증지표 |
| 손익 시점 | 손익분기 시점 |
| 첫 접점 | 초기 고객 접점 |
| 따라오기 어려운 지점 | 단기간에 복제하기 어려운 핵심 자산 |
| 장소에 남는 기록 / 그때그때의 질문 | 축적되는 지속형 정보 / 시점별 질문과 답변 |

### 7-7. 볼드는 조사 앞까지, 의미 단위 전체를 감싼다

- ✗ `**맛집·카페 등 방문할 장소에 대한** 정보를`
- ✓ `**맛집·카페 등 방문할 장소에 대한 정보**를`
- ✗ `**국가승인통계에서 확인되는 사실** — 통계청·법무부 「…」`
- ✓ `**국가승인통계에서 확인되는 사실 — 통계청·법무부 「…」**`

### 7-8. 순위·목록은 순서대로, 한 줄에 하나

- ✗ `- 3위 문화 차이 27.8%, 2위 외로움 28.8%`
- ✓ `- 2위 외로움 28.8%` / `- 3위 문화 차이 27.8%` (각각 별도 줄)

### 7-9. 불완전 명사구를 완성한다

- ✗ `은행·시군구청 등 기관 이용 12.7%`
- ✓ `은행·시군구청 등 **기관 이용의 어려움** 12.7%`

### 7-10. 표기 통일

- `As is → To be` ✗ / `As-is → To-be` ✓
- 영문 고유명사는 원문 표기 유지(K-beauty, Facebook, Yelp)

## 8. 그 밖의 표기 규칙
- 영문 고유명사는 원문 표기를 유지합니다(K-beauty, Facebook, Reddit, Yelp). 한글로 바꾸지 않습니다.
- 굵게 강조는 항목 라벨이 아니라 **문장 속 핵심 구절**에 붙입니다.
