## 1. 서비스 효과성 검증 지표

> 서비스 이용 전·후 KPI 변화를 성장 전략 및 사업화 계획의 근거로 사용

- 등록·확보된 리뷰 수 — 국가별 분리 집계
- 리뷰 조회수 및 저장·클릭 수
- 쿠폰 발급 수 및 사용률
- **리뷰 노출 이후 실제 매장 방문자 수 증가율** — 국가별 분리 집계
- 방문자 대비 리뷰 작성률, 재방문율

매장 효과를 지표에 넣은 이유는 리뷰가 매출로 이어진다는 점이 이미 검증되어 있기 때문입니다. 미국 Yelp를 대상으로 한 연구에서 별점이 1점 오르면 체인이 아닌 독립 식당의 매출이 5~9% 증가하는 것으로 나타났습니다(Luca, 2016). 저희는 같은 흐름을 "리뷰 노출 → 방문 → 매출"로 파일럿에서 직접 측정하고, 그 결과를 매장 제휴 단가의 근거로 사용하겠습니다.

**[표 1] 1차 실증(1개 대학 인근·매장 30곳) 목표치**

| 구분 | 지표 | 목표 |
| --- | --- | --- |
| 콘텐츠 | 등록 리뷰 수 | 매장당 5건 × 30곳 = 150건 |
| 탐색 | 리뷰 1건당 조회수 | 20회 이상 |
| 전환 | 쿠폰 발급 대비 사용률 | 30% 이상 |
| 매장 효과 | 외국인 방문자 수 증가율 | 20% 이상 |
| 지속 | 방문자 대비 리뷰 작성률 | 25% 이상 |

> 위 목표치는 실측값이 없는 상태에서 세운 **가정값**입니다. 1차 실증이 끝나면 실측값으로 교체하고, 이후 목표는 그 값을 기준으로 다시 설정합니다.

## 2. 아이디어의 개발 방안

### 2-1. 초기 데이터 확보 방법

필요 데이터를 장소·유저·리뷰 세 가지로 구분하여 확보 경로를 확정. 규모·분포를 뒷받침할 공공 통계는 별도로 정리.

**① 장소 데이터 — 공공 개방 데이터 + 한국관광공사 TourAPI⁶ 결합**

- 소상공인시장진흥공단 상가(상권)정보 — 전국 영업 중 상가업소의 상호명·업종·주소·**경도·위도** 제공, 분기 갱신(2026.06.30. 기준본)
- 업종 분류 — 표준산업분류 10차 기준 대분류 10 / 중분류 75 / 소분류 247, 카테고리 체계 그대로 사용 가능
- 한국관광공사 TourAPI — 관광정보 약 26만 건, 인증키 발급 후 조회
- 확보 상태 — 경로 확정, 적재 작업 잔여

타 플랫폼의 리뷰를 수집하지 않고 공식 개방 데이터만으로 장소 데이터베이스를 채울 수 있도록 경로를 잡았습니다. 서비스가 커진 뒤에 데이터 출처가 문제가 되지 않도록 처음부터 개방 데이터로 한정한 것입니다.

**② 유저 데이터 — 수집 시점을 세 곳으로 분리**

| 시점 | 받는 항목 | 이유 |
| --- | --- | --- |
| 가입 | 국적, 언어 | 항목이 많으면 가입 도중 이탈하므로 최소화 |
| 마이페이지 | 피부타입, 식문화, 알레르기, 체류기간 | 본인이 원할 때만 선택 입력 |
| 리뷰 작성 | 방문 목적, 동행 여부 | 리뷰 맥락 정보로만 사용 |

**③ 리뷰 데이터 — 앰배서더⁴·파일럿 참가자가 직접 작성**

- 초기 리뷰 부재 시 조건 필터를 걸면 결과가 비는 문제 발생 → 지역·카테고리를 좁혀 밀도부터 확보
- 1차 범위 — 1개 대학 인근, 음식점·카페·뷰티 30개 매장
- 작성 유도 방법 — 2-3에서 상술

**④ 근거 통계 — 공공 원자료로 규모·분포 보완**

- 법무부 「2025 출입국·외국인정책 통계연보」 — 국적별·체류자격별·시군구별 체류외국인
- 한국교육개발원 외국인 유학생 현황 — 대학별 유학생 수, TOPIK 등급 분포
- 통계청 이민자 체류실태 및 고용조사 원자료 — 한국어 능력·주거·소득·소비
- 자체 조사로 기능 우선순위를 정하고, 규모·분포는 위 국가승인통계로 산정

### 2-2. 유저 확보 방법

**온라인**

- 공식 SNS 채널 콘텐츠를 통한 바이럴 및 유입
- 국적별 채널 분리 운영 — 베트남 Facebook, 중국 샤오홍슈 계열, 영어권 Instagram·Reddit
- 국제처 면담에서 국적별로 주로 쓰는 채널이 다르고, Google 기반 서비스를 거의 쓰지 않는 국적도 있다는 점이 확인되었습니다

**오프라인**

- 대학 국제처·한국어교육원 신입생 오리엔테이션 안내
- 외국인 커뮤니티 및 언어교환 모임 참여·홍보
- 국적·관심사 입력 후 자국 리뷰 피드를 바로 보여주는 온보딩 구성

첫 접점을 입국 직후로 잡은 이유는 그 시점에 정보 수요가 가장 크기 때문입니다. 어학연수 비자(D-4-1⁷) 대상자는 입국 전 2학기 이상 등록을 확정하고 오므로 최소 6개월에서 1년의 체류가 보장되고, 입국 직후에 비자·외국인등록증(ARC⁸)·은행 계좌·전화번호 등 행정 절차가 몰립니다. 유학 비자(D-2) 대상자는 대학 입학허가서가 필요하므로 국제처·입학처를 통해 같은 시점에 접근할 수 있습니다.

### 2-3. 추후 플랫폼 활성화 계획

리뷰 작성 유도 방법 세 가지

1. **첫 리뷰 미션** — 가입 후 3일 이내 첫 리뷰 작성 시 기프티콘 등 현금성 보상 지급
2. **앰배서더 선정** — 리뷰를 많이 쓴 이용자를 국적별·지역별 앰배서더로 선정, 랭킹 노출 및 브랜드 협찬 연결
3. **작성 부담 축소** — 별점과 태그 선택만으로 리뷰 1건 완성, 사진 첨부는 필수 조건에서 제외

보상을 현금성으로 잡은 것은 자체 조사 결과를 따른 것입니다. 선호하는 인센티브를 물었을 때 현금 보상이 60%로 가장 높았고 포인트는 16%에 그쳤습니다.

이 가운데 앰배서더 선정은 다른 서비스에서 성과가 확인된 방식입니다. 비건이라는 개인 조건으로 장소를 거르는 리뷰 플랫폼 HappyCow는 앰배서더 제도와 함께 운영하여 185개국 24만 곳 이상의 등록 업소와 187만 건 이상의 리뷰를 확보하였고 현재 600명 이상의 앰배서더가 활동하고 있습니다. 국내에서는 화해가 피부타입·연령별 랭킹으로 리뷰를 걸러 보여주는 방식으로 650만 건의 리뷰를 축적하였습니다. 두 서비스 모두 큰 자본을 들이지 않고, 나와 조건이 같은 사람의 리뷰를 보여준다는 점만으로 이용자가 직접 리뷰를 쓰게 만들었습니다.

커뮤니티는 리뷰와 분리하여 운영합니다. 리뷰는 장소에 남는 기록이고 커뮤니티는 그때그때의 질문이므로, 한 화면에 섞으면 둘 다 잘 쓰이지 않습니다. 커뮤니티는 사진 첨부를 요구하지 않고 짧은 질문도 올릴 수 있게 하여 진입 문턱을 낮추었습니다.

## 3. 아이디어 구체화 과정에서의 한계 및 해결방안

### 3-1. 어떤 문제와 한계가 발생했는가

1. **초기 사용자 및 리뷰 데이터 부족** — 리뷰가 없으면 조건 필터를 걸었을 때 결과가 비어 서비스의 핵심 기능이 작동하지 않음
2. **외국인 이용자 확보 및 지속 참여 유도의 어려움** — 국적별로 사용하는 채널이 달라 단일 채널 홍보가 통하지 않음
3. **리뷰 신뢰성 및 광고성 콘텐츠 관리** — 리뷰가 늘어날수록 협찬·광고성 리뷰가 함께 늘어나는 구조
4. **실제 방문 여부 및 서비스 효과 측정의 어려움** — 리뷰를 봤다는 사실과 매장을 방문했다는 사실을 연결할 수단 부재
5. **기술적·운영적 한계** — 프로토타입 개발 중 실제로 발생한 문제
   - 지도 컴포넌트가 화면 갱신마다 다시 생성되어 입력 중 화면이 멈추는 현상
   - 기능을 늘릴수록 화면 요소가 많아져 외국인 이용자에게 오히려 진입 장벽이 되는 문제
   - 서버·DB 미구축 상태로 작성한 리뷰가 저장되지 않는 문제

### 3-2. 왜 이러한 문제가 발생하는가

리뷰 플랫폼은 이용자가 콘텐츠를 만들어야 가치가 생기는 구조입니다. 그래서 초기에는 볼 것이 없어 사람이 오지 않고, 사람이 없어 리뷰가 쌓이지 않는 상태에 빠집니다. 저희 서비스는 여기에 조건 필터가 더해져 있어, 전체 리뷰 수가 아니라 **특정 국적·조건 조합별 리뷰 수**가 일정 수준을 넘어야 쓸모가 생깁니다. 즉 같은 리뷰 수라도 넓게 흩어지면 작동하지 않습니다.

리뷰 신뢰 문제는 플랫폼이 성장할수록 함께 커지는 구조적 문제입니다. 미국 Yelp를 분석한 연구에서도 식당 리뷰의 약 16%가 의심 리뷰로 걸러지며 그 비중이 시간이 갈수록 커진 것으로 보고되었습니다(Luca·Zervas, 2016). 사후에 걸러내는 방식만으로는 운영 부담이 커지고, 이미 읽은 이용자에게는 소용이 없습니다.

기술적 문제는 기능을 먼저 늘리고 구조를 나중에 정리한 데서 비롯되었습니다. 화면 갱신 방식을 정리하지 않은 채 지도·필터·커뮤니티를 차례로 붙이면서, 한 곳을 고치면 다른 곳이 느려지는 상태가 되었습니다.

### 3-3. 어떻게 해결할 것인가

**[표 2] 한계와 대응 방안**

| 한계 | 대응 방안 |
| --- | --- |
| 초기 리뷰 부족 | MVP¹ 필수 기능과 추후 기능을 구분하고, 1개 대학 인근·30개 매장으로 범위를 좁혀 조건별 리뷰 밀도부터 확보 |
| 이용자 확보·참여 유도 | 대학 국제처 온보딩 + 국적별 채널 분리 운영 + 첫 리뷰 미션·앰배서더 선정 |
| 리뷰 신뢰성 | 사후 삭제가 아니라 작성자 조건과 협찬 여부를 리뷰와 함께 표시하여 이용자가 직접 판단하도록 함. 앰배서더는 활동 이력이 공개되므로 작성자 검증 역할을 겸함 |
| 방문·효과 측정 | 쿠폰 발급·사용 기록, 매장 QR, 제휴 매장의 방문 집계를 결합하여 리뷰 노출부터 방문까지를 연결 |
| 화면 갱신 성능 | 화면 갱신을 한 번에 모아 처리하도록 구조 변경, 지도는 재생성하지 않고 유지하도록 수정(적용 완료) |
| 화면 복잡도 | 장소 상세에서 먼저 보여줄 항목을 다섯 개로 제한하고, 모바일 하단 탭을 다섯 개 이하로 고정 |
| 데이터 저장 | Firebase⁹ 연동으로 회원·리뷰 저장 구현 예정. 화면과 데이터 구조는 저장 기능에 맞추어 미리 설계 완료 |

### 3-4. 현재 해결된 부분과 향후 해결할 부분

**이미 검증·해결한 것**

- 화면 갱신 성능 문제 — 갱신을 모아 처리하는 방식으로 수정, 지도 재생성 제거
- 화면 복잡도 — 표시 항목 수 제한 및 모바일 하단 탭 구조 적용
- 조건 필터 동작 — 국적·인종·피부타입 조건으로 리뷰가 실제로 걸러지는 것까지 프로토타입에서 확인
- 로그인 — 구글 계정 연동으로 실제 인증 동작 확인
- 데이터 출처 적법성 — 공공 개방 데이터·공공 API로 한정

**MVP 단계에서 검증할 것**

- 조건별 리뷰가 몇 건 이상 쌓여야 이용자가 쓸모를 느끼는지
- 첫 리뷰 미션과 앰배서더 선정이 실제 작성률을 올리는지
- 쿠폰을 통한 방문 연결이 매장에 유의미한 증가로 나타나는지

**확장 이후 기술·데이터로 고도화할 것**

- 리뷰 신뢰도 자동 판별 및 협찬 표시 누락 탐지
- 국적·조건별 추천 정확도 개선
- 매장용 리포트 자동 생성

프로토타입은 화면 시안이 아니라 직접 클릭하여 화면 이동을 확인할 수 있는 형태이고 인터넷 주소로 공개되어 있어, 심사 과정에서 바로 시연할 수 있습니다. MVP를 외주 없이 팀 내 인력이 직접 제작하였기 때문에 조사에서 나온 의견을 제품에 반영하는 데 걸리는 시간이 짧고, 초기 유입에 필요한 콘텐츠 제작과 외국인 접점도 팀 안에 있습니다.

## 5. 차별화 방안

### 5-1. 기존 서비스와의 차이

**[표 4] 기존 서비스와 GLOU 비교**

| 구분 | 기존 서비스 | GLOU |
| --- | --- | --- |
| 리뷰 기준 | 한국인 이용자 기준의 별점과 후기 | 작성자의 국적·체류기간·피부타입·식문화가 함께 표시 |
| 탐색 방식 | 전체 평점 순 정렬 | 나와 조건이 같은 사람의 리뷰만 보는 맞춤 필터링 |
| 정보 구조 | 텍스트 후기 중심 | 영어 가능·외국 카드 결제·한국 번호 필요 여부를 항목으로 표준화 |
| 화면 설계 | 한국어 사용자 기준 정보 밀도 | 외국인이 편해하는 저맥락 디자인⁵ |
| 콘텐츠 생산자 | 일반 이용자 또는 협찬 크리에이터 | 국적별·지역별 앰배서더가 순위와 함께 노출 |
| 매장 연결 | 화면 노출까지 | 쿠폰·이벤트로 방문까지 연결하고 결과를 데이터로 회신 |

### 5-2. 저맥락 디자인의 근거가 된 화면 조사

외국인 이용자가 한국 서비스에서 어디에 막히는지 확인하기 위해, 외국인 대상 한국 서비스와 해외 리뷰·커뮤니티 서비스를 직접 설치하여 화면 단위로 비교하였습니다. 어느 서비스가 좋다는 평가가 아니라 각 화면에서 무엇을 보고 무엇을 못 보는지를 기준으로 정리하였고, 그 결과를 MVP 화면에 그대로 반영하였습니다.

조사한 서비스와 적용 내용

- **Creatrip** — 필터에 English Available이 별도 항목으로 있고 상품 카드에 쿠폰 배지가 붙음 → 영어 가능 여부를 태그가 아닌 필터 항목으로 승격, 장소 카드에 쿠폰 표시 추가
- **CatchTable Global** — 한국 전화번호 없이 예약 가능하다는 점을 화면에서 먼저 안내 → "한국 번호 필요 없음"을 장소 상세 상단에 고정
- **네이버지도·카카오맵** — 한국어 사용자 기준으로 정보량이 많아 처음 온 외국인은 어디부터 볼지 판단이 어려움 → 장소 상세 첫 화면 표시 항목을 다섯 개로 제한
- **Yelp** — 하단 탭이 다섯 개를 넘지 않고 탭 이름이 한 단어 → 모바일 하단 탭 다섯 개 제한, 아이콘 + 한 단어 구성
- **샤오홍슈** — 두 칸 격자 피드와 짧은 글 형식이라 읽는 부담이 적음 → 커뮤니티·숏폼 두 칸 격자 배치, 사진 첨부 필수 해제
- **당근** — 지역 커뮤니티가 지도·거래와 분리된 별도 탭 → 커뮤니티를 리뷰와 섞지 않고 별도 탭으로 분리
- **무신사** — 체형 조건을 넣으면 그 조건의 후기만 보이는 필터가 리뷰 안에 있음 → 맞춤 필터를 별도 화면이 아니라 리뷰 목록 안에 배치

조사에서 공통으로 확인한 것은, 외국인 이용자가 막히는 지점이 언어 자체보다 "이 가게에서 내가 결제와 예약을 할 수 있는가"를 방문 전에 알 수 없다는 데 있다는 점이었습니다. 이에 설명을 읽지 않아도 화면에 보이는 것만으로 뜻이 통하도록 항목 수를 제한하고, 판단에 필요한 정보를 장소 상세 첫 화면에 고정하였습니다.

### 5-3. 맞춤 필터링이 통한다는 근거

핵심 차별점은 화면을 외국어로 번역해 주는 데 있지 않고, 이용자가 입력한 조건에 따라 화면에 나오는 리뷰 목록 자체가 달라진다는 데 있습니다. 무신사는 체형이 비슷한 구매자의 후기를 골라 볼 수 있게 하는 등 개인화를 강화한 뒤 개인화 추천 영역의 구매 전환율이 약 3배 증가하였다고 밝힌 바 있습니다. 저희는 같은 방식을 의류 체형이 아니라 국적·피부타입·식문화에 적용하였습니다.

### 5-4. 후발주자의 진입 장벽

후발 경쟁자가 따라오기 어려운 지점은 **국적·조건별로 쌓인 리뷰**와 **그 리뷰를 만드는 앰배서더 네트워크** 두 가지입니다.

국적별 리뷰는 한 나라의 리뷰가 일정 수 이상 쌓여야 다음 이용자에게 쓸모가 생기고, 그 이용자가 다시 리뷰를 남깁니다. 따라서 지역과 국적을 좁혀 그 안에서 먼저 리뷰 수를 채운 쪽이 유리하며, 뒤에 오는 곳은 같은 조합에서 처음부터 다시 쌓아야 합니다. 병원 리뷰 플랫폼 모두닥이 제휴 병원 250곳에 누적 리뷰 53만 건, 병원당 약 2,100건을 확보한 뒤 광고 매출을 올린 것이 같은 구조입니다.

앰배서더 네트워크는 사람과 관계로 만들어지므로 자금만으로 단기간에 복제하기 어렵습니다.

반면 **대학 국제처 접근 경로는 저희만의 것이 아닙니다.** 외국인 체류 행정 서비스인 하이어비자가 이미 105개 이상 대학과 협약을 맺고 있습니다. 저희는 이 경로를 두고 다투기보다 **행정 서비스를 마친 이용자에게 생활 정보를 잇는 제휴**로 접근합니다.

## 각주

1. **MVP(Minimum Viable Product, 최소기능제품)** — 핵심 기능만 구현하여 시장 반응을 확인하는 초기 제품
2. **Fit Review** — 이용자가 미리 입력한 조건(국적·인종·피부타입)과 일치하는 작성자의 리뷰만 골라 보는 필터. GLOU 자체 명칭
3. **GLOU Check** — 영어 메뉴 유무, 외국 카드 결제 가능 여부, 한국 전화번호·예약 필요 여부, 혼자 방문 가능 여부, 가격대를 항목으로 표준화한 장소 정보. GLOU 자체 명칭
4. **앰배서더(Ambassador)** — 리뷰와 콘텐츠를 꾸준히 생산하여 서비스가 공식 인증한 이용자. 국적별·지역별 순위 공개
5. **저맥락(Low-context) 디자인** — 사전 지식이나 배경 설명 없이 화면에 보이는 것만으로 뜻이 통하도록 구성한 화면. 다국적 이용자 대상 설계 방식
6. **TourAPI** — 한국관광공사가 개방한 관광정보 조회용 공공 API. 인증키 발급 후 사용
7. **D-4-1 비자 / D-2 비자** — 각각 대학 부설 어학원 어학연수생, 대학 정규 학위과정 유학생에게 발급되는 체류자격
8. **ARC(외국인등록증)** — 91일 이상 체류 외국인이 발급받는 신분증. 은행 계좌 개설·휴대전화 개통의 선행 조건
9. **Firebase** — 구글이 제공하는 서버·데이터베이스·인증 통합 서비스. 서버를 직접 구축하지 않고 이용 가능
