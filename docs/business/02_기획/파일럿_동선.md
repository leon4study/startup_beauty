# GLOU 파일럿 동선 (콘텐츠 → 신청 → 방문 → 리뷰)

> 목적: 실증(파일럿)에서 "이용 의향"이 아닌 **실제 행동**을 측정.
> (증거 우선순위: 실제 이용·제휴 > 사전신청 > 인터뷰 > 설문)
> 대상: 파일럿 참여자 10~15명 · 제휴매장 5곳+ · 다국어 검증 리뷰 30개+ (사업계획서 6장 목표와 일치)

---

## 1. 핵심 동선 (5단계 루프)

| 단계 | 화면/도구 | 유저 행동 | 수집 데이터 | 전환 지표 |
|---|---|---|---|---|
| **① 발견** | 커뮤니티·쇼츠 피드 · 리뷰 지도 | 국적별 콘텐츠·장소·행사 탐색 | 조회·저장·클릭 | 피드→상세 클릭률 |
| **② 상세/관심** | 장소·행사 상세(이용정보 요약 · 이벤트 카드) | 저장(찜) · 행사 확인 | 저장 수 · 체류시간 | 상세 저장률 |
| **③ 신청** | 신청폼(이벤트·체험) | 이름·연락·방문희망일 입력 | 신청 수 · 연락처 | 상세→신청 전환율 |
| **④ 방문** | 제휴매장/행사 + 쿠폰·체험권 | 오프라인 방문 · 쿠폰 사용 | 방문 인증(코드·사진) | 신청→방문 전환율 |
| **⑤ 리뷰** | 리뷰 작성 화면(별점·해시태그·사진) | 국적/피부 태그 리뷰 작성 | 리뷰 수·태그·사진 | 방문→리뷰 전환율 |

→ ⑤에서 쌓인 리뷰가 다음 유저의 **①발견 신뢰도**를 올림 = 콜드스타트 극복 루프.

---

## 2. 단계별 설계 원칙

- **① 발견** — 샤오홍슈형 피드(콘텐츠 소비) + 오늘의집형 **콘텐츠→장소/행사 전환**(쇼츠 상품 태그→장소 상세, 글→장소 보기). 이미 프로토타입에 반영.
- **③ 신청폼** — 1차 파일럿은 **구글폼/노션폼**으로 시작(네이티브 앱·자체 결제 회피 = 사업계획서 MVP 비범위와 일치). 폼에서 매장·날짜·국적 수집. 2차에 인앱 폼 내재화.
- **④ 방문** — 제휴매장에 쿠폰코드/체험권 제공 → 방문 시 코드·사진으로 인증. 결제·정산 자금 보관은 하지 않음(정보·연결까지).
- **⑤ 리뷰** — 방문 후 앱(또는 링크)에서 국적·피부 태그 리뷰 작성 → 국적별 검증 리뷰 데이터. 편집기 완성됨.

---

## 3. 프로토타입 매핑 (현황 vs 필요)

| 단계 | 프로토타입 현황 | 남은 제작 |
|---|---|---|
| ① 발견 | ✅ 커뮤니티·쇼츠·리뷰지도 | — |
| ② 상세 | 🟡 리뷰형 상세만 | **이용정보 요약 영역** + **기간행사/이벤트 카드** |
| ③ 신청 | 🔴 없음 | **신청폼 연결**(1차 구글폼 버튼 → 2차 인앱) |
| ④ 방문 | 🔴 없음 | 쿠폰코드·방문 인증(선택) |
| ⑤ 리뷰 | ✅ 전체화면 편집기+해시태그 | 신청→리뷰 연결 |

---

## 4. 우선 제작 순서 (동선 완주용)

1. **장소·행사 상세** — 이용정보 요약 영역 + 기간행사/이벤트 카드 추가 (②)
2. **신청폼 연결** — 상세에 "신청하기" → 구글폼 링크(1차) (③)
3. **신청→방문→리뷰** 연결 — 방문 후 리뷰 유도 동선 (⑤)
4. (선택) 쿠폰코드·방문 인증 (④)

---

## 5. 모바일 네비 구조 검토

- **현재**: 리뷰 · 커뮤니티 · 쇼츠 · 앰배서더 · 마이
- **동선 반영 제안**: 발견(Discover) · 지도(Map) · **작성(Create·＋)** · 커뮤니티 · 마이
  - 앰배서더 랭킹 → 커뮤니티/프로필에 흡수
  - 이벤트 → 별도 탭보다 **발견·상세 내 카드**로 노출(동선 단순화)
  - 쇼츠 → 발견/커뮤니티 내부 콘텐츠로 통합 가능

---

## 6. 실증(제출용) 연동

- 각 단계 **전환율**(발견→상세→신청→방문→리뷰) = 지자체·심사 제출 성과지표.
- 목표: 파일럿 10~15명 완주 · 제휴매장 5곳+ · 검증 리뷰 30개+ · LOI 1건+.
